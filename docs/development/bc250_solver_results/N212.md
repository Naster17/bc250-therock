## Measured cause and implementation

The initial warm-session profile reports recovery~2.47–5.19ms, preparation
~0.35–0.71ms and full Schur~1.51–9.89ms across six seeded fixtures. At order16,
reference recovery submits18 ATen matrix products,18 max reductions and36 divides.
Eighteen scalar reads remain for the common validation/final-result checks.

Each GPU lane owns one eigenvector column and16 private complex values. Rows
are solved from bottom to top, dividing only active off-diagonal pivots. Positive
homogeneous per-column max-magnitude rescaling follows every row, matching the
N2.6 reference policy. The checked normalized |T|<=1, order<=16 and strict global
8sqrt(eps) gap bound keep squared pivots and intermediate values in range for
these precisions. Public finite/unitary/triangular/separation checks precede the
private stage; common finite/nonzero-norm/unitnorm/triangular-residual and Schur-Q
transform checks follow it with their original bounds. No pivot perturbation,
relaxed tolerance, extra iteration budget or hidden CPU solve was introduced.

The wrapper owns a contiguous resolved input and a fresh output, uses the actual
current GPU stream, and caches only immutable CDLL/function bindings. GEHRD
sessions and their owner/lifetime checks are unchanged. This is a private
prototype ABI with checked-input preconditions, not a new public rocSOLVER API.

- A real GPU trace contains exactly one `small_triangular_backsub<float>` launch
for the isolated captured recovery. All nine process guards acknowledged600s;

with numerical checks reached before it and unchanged kernel logs.104 protected

The first capture run profiled CPU-only before requesting GPU tracing. Its later
trace contains CPU events but zero GPU events, causing the required kernel

WS/recovery/solver-n212-before/validate_solver_n212-first.py). The existing A09
CPU-only-after-GPU test did not cover this reverse order. Native numerical code
and all bounds are identical in both runs.

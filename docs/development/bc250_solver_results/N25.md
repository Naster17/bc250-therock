## Implementation

`gfx1013_schur_candidate.py::_normal_scale` forms a unit-scale GPU matrix using
the maximum absolute real/imaginary component. Componentwise real division avoids
large complex magnitude/division intermediates. Conjugate/negative view bits are
resolved before raw-component inspection. A zero/subnormal distinction uses GPU
integer views of floating representations if floating reductions read zero;
all-subnormal matrices are explicitly refused instead of being mistaken for zero.

`schur` now normalizes before native GEHRD and the existing shifted GPU QR loop.
Convergence/deflation/fill checks run in normalized units. Every return, including
positive-info partial results, restores T to original units with componentwise
multiplication and rejects nonfinite restored output. Finite input need not have
a representable Schur form: a2x2 matrix with all entries0.75×dtype_max has an
eigenvalue1.5×dtype_max, and is explicitly refused on rescaling.

Zero matrices return exact zero T and identity Q with no QR iteration; repeated
zero eigenvectors remain refused. Scalars retain the exact pre-existing trivial
path. Direct standalone `hessenberg` remains the original primitive; the expanded
scale result applies to `schur` and the combined eigenpair pipeline, not a newly
qualified standalone GEHRD range.

Right-vector recovery reuses safe component normalization, then normalizes by
the unit matrix's complex magnitude to preserve its existing separation policy:
minimum pairwise diagonal gap / max(abs(T)) >8sqrt(eps). No pivot perturbation,
iteration-limit increase, fallback or tolerance relaxation. CPU eig/reference
matrices are used only in validation. Candidate arithmetic remains GPU with
Python scalar control/synchronization. Existing native DSOs are reused; no native
compile or cache reset was needed.

## Limits and next

Uniform normal-magnitude scaling in selected fixtures is qualified; arbitrary
mixed dynamic ranges, subnormal arithmetic, balancing, defective/repeated vectors,
robust condition estimation/general convergence, larger matrices, batching,
gradients/graphs, concurrency and sustained/performance remain unqualified.
No claim that normalization makes this Python-controlled prototype fast.

Qualified Torch4ee6571/libraries a6f7d3d, active image/DSOs/prefix metadata, kernel/
boot fallback/power policy/BIOS, .105, user data/checkpoints/builds/caches and
user-owned src/ remain unchanged. Python CPU fault and separate MIOpen defect are
unresolved; neither is the previously fixed CSR/VM-heap corruption.

Next N2.6: measure bounded end-to-end cost and component/host-synchronization
bottlenecks against the existing host eig path with correctness checks, then
choose one measured overhead-reduction step. Keep production dispatch unchanged
until correctness, failure policy and useful measured behavior justify an opt-in.

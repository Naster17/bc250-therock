## Implementation and preserved boundaries

One 32-thread block uses shared matrices to form complex Householder QR of the
shifted active block and perform the full similarity update plus accumulated
Schur-Q transform. Trailing coupling is included after deflation. An exactly
zero reflector column uses the identity; no singular pivot perturbation or host
matrix solve is added. The Python driver still selects shifts, tests convergence,
checks finite/Hessenberg fill and restores original units. The existing
normalization, order cap, iteration budgets, 128eps fill bound, separation and
right-vector residual/refusal gates are unchanged. The default reference step
preserves N2.6's in-place accumulated-Q update and is bitwise equal to that helper
on all six final timing fixtures, including info/iteration/deflation counts.

The shared-object C entry point is private to the helper: it expects owned,
contiguous, matching complex tensors and normalized driver inputs. It is not a
new public rocSOLVER API. The wrapper owns distinct outputs and submits on the
current Torch stream. Production Torch autograd is unchanged; this isolated eig
prototype has no gradients, batching, balancing, graph or general convergence
contract. Real dtype, larger order and requires-grad input remain refused.

An initial single-work-item implementation passed all new direct/model fixtures
but was slower at orders9/16. Its source/binary and successful test report remain
in WS/recovery/solver-n27-serial and logs/solver-step-n27. Cooperative shared-memory
work removed that measured bottleneck. No numerical tolerance was relaxed.

## Bounded cost measurements

Same inputs, one warmup and three synchronized wall samples/pass in
A1(reference)/B1(device)/B2(device)/A2(reference) order. Values below average the
two pass medians. Timings cover Schur only, including Python/library control;
they exclude right-vector recovery and are not kernel-only or whole-model times.

| dtype/order | Reference Schur ms | Device Schur ms | Ratio | Host eig control ms |
| --- | ---: | ---: | ---: | ---: |
| complex64/4 | 12.374 | 10.016 | 1.235 | 0.220 |
| complex64/9 | 24.420 | 17.973 | 1.359 | 0.248 |
| complex64/16 | 42.261 | 28.994 | 1.458 | 0.347 |
| complex128/4 | 14.371 | 11.169 | 1.287 | 0.217 |
| complex128/9 | 32.144 | 22.450 | 1.432 | 0.277 |
| complex128/16 | 52.454 | 36.018 | 1.456 | 0.398 |

Separate synchronized instrumentation splits native GEHRD/reflector-Q preparation,
QR/similarity calls and remaining validation/scaling/shift/deflation control.
At order16 complex64/128, preparation is ~6.10/6.19ms, device QR/similarity
~3.38/6.41ms, remaining work ~22.46/28.24ms. Reference QR/similarity is
~14.68/19.47ms. Instrumentation forces per-call synchronization; these are
single diagnostic phase sums and must not be added to the paired timings or
misrepresented as pure GPU durations. Remaining host-controlled work dominates.

Small sample counts on one board do not establish general or sustained gains.
Even Schur alone remains much slower than the full host eig control. No default
integration, LoRA improvement, universal performance or full GPU eig claim.

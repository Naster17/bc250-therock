# N2.6 small native eig profile and recovery vectorization — 2026-10-16

Vectorized the isolated candidate's triangular right-eigenvector recovery after
profiling identified its quadratic loop/host scalar checks as a major cost.
107 retained correctness/refusal groups pass. Six paired timing fixtures show
recovery1.53–8.44× and complete-candidate1.07–1.72× reductions in synchronized wall
cost. The optimized native candidate remains far slower than the current host
LAPACK interface at these small sizes, so production dispatch stays unchanged.
No whole-Torch/model or universal performance improvement is claimed.

Source: `build_tools/bc250/gfx1013_schur_candidate.py::right_eigenvectors`.
Measurement helper: `build_tools/bc250/benchmark_solver_n26.py`.

## Profile and selected change

The initial six-fixture profile used complex64/complex128 order4/9/16, known
separated spectra and basis condition target10. At order16 the old recovery cost
was about37ms, versus41/52ms for Schur and79/90ms for the complete candidate.
Torch-level local scalar reads were376 in recovery versus155/203 in Schur.
The host-interface control was about0.35/0.41ms. This supported a recovery change
without claiming that the native candidate should replace the host path.

Old recovery solves each eigenvector separately, with n(n-1)/2 row updates and
multiple host scalar checks per row. New recovery solves all columns together,
with n-1 GPU row updates, masked inactive pivots and homogeneous per-column
rescaling. The already-checked global pairwise separation guarantees every active
pivot exceeds the unchanged8sqrt(eps) floor. Inactive/diagonal pivots are set to1
before division; no zero division is evaluated merely to discard its output.

Because scaled |T|≤1, rescaled |Y|≤1, order≤16 and the floor bounds division,
row intermediates cannot approach dtype overflow in this contract. Finite/norm
checks are deferred to the end of the bounded row loop; the existing triangular
residual guard and normalized GPU Q transform remain. Unsupported/nonconverged/
malformed/close-spectrum policies are unchanged. No singular pivot is perturbed.
The old helper is retained in .104 WS/recovery/solver-n26-before and Git/history.

## Bounded measurements

After input/reference correctness checks, each component is warmed once and
measured with3 synchronized wall-clock samples. Device synchronization occurs
before the timer and after the result; Python dispatch/control and library host
work are intentionally included. No GPU-event duration is misrepresented as pure
kernel time. Schur/recovery/whole component labels overlap and must not be added.
Instrumented runs are separate from latency measurements.

The paired run loads immutable old/new helper modules and uses the same GPU input
in A1/B1/B2/A2 order for recovery and whole-pipeline measurements. Each pass has
one warmup and3 samples; the table averages the two pass medians for each version.
Recovery uses the same converged T,Q, adapting only the dataclass module identity.
Whole-pipeline calls recompute Schur. Both complete candidates and the host control
are checked against CPU complex128 eigenvalues, residuals and vector projectors.

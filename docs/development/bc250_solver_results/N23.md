# N2.3 native small complex Schur prototype — 2026-10-15

An isolated GPU matrix-arithmetic prototype now reduces a small complex matrix
to Hessenberg form and performs bounded shifted QR to obtain a Schur form.
It passes21 bounded groups on .104. The candidate is capped at order16 and is
**not installed into Torch eig dispatch**. The working N2.2 host-LAPACK default
remains unchanged. This does not complete a native general-purpose eigensolver.

Implementation: `build_tools/bc250/gfx1013_schur_candidate.py`.
References/failure gates: `build_tools/bc250/validate_solver_n23.py`.

## Reuse audit and selected step

Pinned Torch4ee6571 and ROCm libraries a6f7d3d already provide native components:

- rocSOLVER `roclapack_gehrd.cpp/.hpp`: complex GEHRD, blocked/unblocked machinery,
  packed Householder reflectors and device tau. Its public C/Zgehrd API uses
  one-based ilo/ihi, column-major lda and n-1 device tau entries. Source defaults
  are block64 and unblocked switch512; this candidate exercises small/unblocked
  reduction, not the larger blocked GEHRD regime.
- No geev/hseqr/lahqr/gees implementation was found in the pinned rocSOLVER source.
  Native nonsymmetric Schur iteration/vector recovery cannot be obtained merely
  by enabling an architecture or changing the existing host wrapper.
- Torch GPU QR (`BatchLinearAlgebra.cpp::geqrf_kernel`, `orgqr_kernel_impl`) uses
  the solver path for these single matrices. `BatchLinearAlgebraLib.cpp` calls
  GEQRF/ORGQR specializations; hipSOLVER complex generic64 GEQRF forwards to
  rocSOLVER C/Zgeqrf_64, and complex ORGQR to C/Zungqr. These are GPU routines,
  unlike hipSOLVER Xgeev's host-LAPACK implementation.
- GPU tensor GEMM, complex arithmetic, norms and masks suffice to build a bounded
  explicit QR prototype without adding a compiled library/API or changing DSOs.
  Audited source hashes and loaded runtime identities are retained in `n23/`.

A full native Schur driver plus eigenvector recovery/integration would be a much
larger change. The selected step implements small Schur similarity and explicit
nonconvergence first, allowing independent checks before any production dispatch.

## Implementation and contract

`hessenberg(A)` calls native rocSOLVER C/Zgehrd through typed ctypes bindings on
an owned column-major copy. A private rocBLAS handle is assigned the current GPU
stream and destroyed in finally; statuses are checked. Q is reconstructed from
the device reflectors with GPU operations, returning H,Q with A≈Q H Qᴴ. The
original input is never overwritten, including column-major inputs that could
otherwise alias a contiguous conversion.

`schur(A, max_iterations=256)` accepts one finite gfx1013 complex64/complex128
matrix of order1..16, without autograd. It uses the closest eigenvalue of the
trailing2x2 block as a complex single shift, explicit GPU QR, full two-sided
similarity updates and accumulated Q. Every20 unsuccessful steps it uses a
deterministic exceptional shift. It removes only checked below-Hessenberg
roundoff fill and deflates a bottom subdiagonal only below eps×local-diagonal
scale plus safe minimum. Nonfinite iterates/unexpected fill raise an error.

The global QR budget is an integer0..4096. `SchurResult.info==0` indicates the
candidate's Schur convergence; positive info reports the remaining leading active
block, with partial T,Q and iteration/deflation counts. Budget exhaustion does
not call LAPACK or report a successful spectrum. Triangular/scalar inputs can
complete with zero QR steps. Q contains **Schur vectors**, not nonsymmetric right
eigenvectors. T's diagonal is interpreted as the spectrum only after info==0.

Matrix arithmetic stays on the GPU, using the current stream. Python controls
iterations and reads scalar convergence/shift/fill tests, which synchronizes the
host. This is not an all-device driver, fused implementation or performance
optimization. Candidate code contains no CPU eig/QR or host matrix transfer.
CPU complex128 eigenvalues and reconstruction calculations occur only in the
validation script after candidate execution. No native compilation was needed:
the prototype composes the already-built qualified GPU libraries; caches retained.

## Tests and evidence

Final label `.104 WS/logs/solver-schur-n23-final` passes21 groups:

- Twelve complex64/complex128 fixtures at orders4/9/16 and basis conditions1/10,
  using known separated complex spectra and normal/nonnormal matrices. Direct
  Hessenberg similarity/unitarity, full Schur similarity/unitarity, exact stored
  Hessenberg/triangular structure, analytic and CPU eigenvalues are checked.
  Padded/transposed input guards remain exact; calls use nondefault streams with
  explicit producer/consumer waits, and all result matrices are on the GPU.
- Two grouped nonconvergence cases each exhaust budgets0 and1 on nontrivial9x9
  input. Positive info, exact consumed budget, unchanged input and meaningful
  partial Schur similarity are required; no implicit host fallback.
- Two already-triangular repeated-eigenvalue fixtures complete with budget0.
  They do not qualify eigenvectors of a defective matrix.
- Two2x2 rotation fixtures require nonreal eigenvalues ±i (one QR iteration).
- Two scalar fixtures complete with budget0 and exact results.
- One grouped argument gate rejects9 unsupported input/budget settings.

## Limits and next implementation

This is an experimental reference prototype at selected small dimensions, with
moderate finite scales/basis conditioning. There is no balancing, stable scaling
for extreme values, general defective/clustered-spectrum convergence guarantee,
right/left eigenvector recovery, batching, gradients, compiled/graph execution,
multistream/concurrency, larger/blocked-GEHRD, performance or sustained claim.
Bounded iteration failure is qualified; arbitrary failure/OOM/hardware hangs are
not. No conclusion that the method is fast follows from successful correctness.

Torch source/DSOs/dispatch, prefix metadata, boot/kernel/fallback, SDMA/heap-off,
math defaults, power policy/BIOS and .105 are unchanged. Python CPU fault and
MIOpen elapsed/workspace defect remain separate unresolved issues. User data,
checkpoints, source histories, caches and user-owned src/ are retained.

Next N2.4: recover right eigenvectors from a converged small complex Schur form
using guarded triangular back-substitution and GPU Q transforms. Begin with
separated spectra, CPU/analytic eigenpair residual and phase-independent direction
checks, plus explicit repeated/near-singular/nonconverged refusal. Keep production
eig dispatch unchanged until the candidate and its failure contracts are ready.

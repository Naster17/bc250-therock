# N2.9 bounded device iteration chunks — 2026-10-18

Completed the recorded prototype scope: explicit
`schur(a, qr_backend="device_chunked", chunk_size=16)` groups up to16 N2.8
control steps per GPU launch/status transfer. Chunk sizes1..32 are accepted;
total QR budget, terminal status and immediate failure semantics are preserved.
The default helper remains `reference`, and production eig remains host LAPACK.

The result is mixed: status transfers fall sharply, but measured whole-candidate
latency improves only slightly at orders4/9 and regresses at16. No default
integration or broad/model speedup is justified.

## Implementation and verification

The N2.8 control arithmetic is extracted into a shared device function. A
32-thread chunk kernel calls it repeatedly, stopping immediately on convergence,
budget exhaustion or nonfinite/excess-fill status. Separate current-T/Q shared
buffers avoid Q input/output aliasing; each row update needs its old columns.
There are at most ceil((budget+1)/chunk_size) host launches. The extra logical
step allows deflation/convergence checks after the last permitted QR, preserving
deflation-before-budget semantics. One five-int D2H status returns per launch.

Normalization, complex64/128 cap16, QR budget0..4096, deflation/shift/exceptional
shift rules, finite/128eps fill bound, 8sqrt(eps) recovery separation and residual
bounds are unchanged. Unsupported public chunk values and nondefault chunks for
other backends are rejected before scalar/zero shortcuts. Private C/device APIs
expect valid normalized contiguous inputs/state, not arbitrary public matrices.

Qualified original/unpadded candidate passes:

- All128 unchanged N2.3–5 Schur/eigenvector/scale/separation/failure groups.
- 74 N2.8-style single-step Python-oracle checks using chunk_size1, including
  nondefault streams, QR phase alignment, shift branches, deflation boundaries,
  zero budget, nonfinite/excess fill and input immutability at fixed tolerances.
- 100 chunk-boundary cases: both complex dtypes, orders4/16, chunks1/2/8/16/32,
  budgets0/1/7/17/33 and since-deflation19. One chunk agrees bitwise in T/Q and
  exactly in state with repeated calls to the same compiled kernel at chunk1.
- Four long-chunk nonfinite/fill cases stop at the first failed iteration with
  unchanged zero completed-iteration count, rather than continuing after failure.
- Six full CPU complex128 eigenpair/residual/projector fixtures at4/9/16, using
  reference, N2.8, N2.9 and host controls. Existing residual8e-6/4e-12 and
  eigenvalue/projector8e-4/6e-10 bounds unchanged. Complete results and counters
  agree exactly across chunks1/2/8/16/32 on these fixtures. Default reference
  remains exactly equal to immutable N2.8 on the same inputs.
- Seven public chunk-option refusals, budget0/1 partial/recovery-refusal checks,
  real `small_schur_chunk` GPU trace and unchanged input checks pass.

A padded-Q shared-memory variant also passes these checks plus128 retained groups,
but does not improve the timing result. It was not selected. Its source/binary
remain in WS/recovery/solver-n29-padded and ignored local artifacts. The simpler
original source/binary was restored under the exclusive lock, then checked
against its already-passed result hashes; no new GPU run was needed for an
identical artifact. All12 GPU guards across both variants are acknowledged600s,
all processes exit0 and before/after dmesg is byte-identical. No tolerance or
iteration limit was increased. Both build/test histories are retained in n29/.

## Bounded timing result

Same inputs, one warmup and three synchronized wall samples per
A1(N2.8)/B1(N2.9)/B2(N2.9)/A2(N2.8) pass. Values average the two medians per
version. Schur includes preparation/control; whole includes right-vector recovery.
Wall times include host overhead, not pure kernel durations.

| dtype/order | Schur N2.8→N2.9 ms | Whole N2.8→N2.9 ms | Whole ratio | Status copies N2.8→N2.9 |
| --- | ---: | ---: | ---: | ---: |
| complex64/4 | 6.058→5.730 | 8.844→8.550 | 1.034 | 8→1 |
| complex64/9 | 7.744→7.241 | 11.419→10.914 | 1.046 | 20→2 |
| complex64/16 | 11.352→11.584 | 16.184→16.447 | 0.984 | 35→3 |
| complex128/4 | 6.319→6.037 | 9.083→8.734 | 1.040 | 11→1 |
| complex128/9 | 8.781→8.293 | 12.441→11.888 | 1.047 | 26→2 |
| complex128/16 | 15.236→16.393 | 20.136→21.180 | 0.951 | 46→3 |

The padded experiment similarly regresses at16 (whole ratios0.973/0.942).
Reduced transfers therefore do not establish a latency gain. Additional shared
input traffic/kernel execution costs remain candidates for profiling; no physical
bank-conflict/counter diagnosis is claimed. Torch-level transfer counts are
separate from timing and do not include all library/runtime synchronization.
Host full eig controls remain~0.224–0.426ms, much faster than even Schur alone.
Six warm-cache fixtures/three samples on one board do not establish general,
sustained, training, LoRA or whole-Torch improvement.
